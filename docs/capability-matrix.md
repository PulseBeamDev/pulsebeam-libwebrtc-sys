# Linux x86_64 capability and evidence matrix

This matrix tracks the approved Linux x86_64 API completeness contract. The public API and evidence links below stand alone. **Pass** means the named test actually exercises the claim with a matching artifact. **Partial** means only the specified subset is exercised. **Gap** means no qualifying API or test exists. Headless tests do not qualify a physical device or all possible libwebrtc background work. Real SFU interoperability belongs to the higher-level project.

**QA boundary:** Qualify our Rust/CXX adapter with focused public-API smoke and integration tests: construction, negotiation/configuration, encoded bypass, representative payload/metadata identity, explicit rejection, backpressure, and shutdown. Trust the pinned upstream libwebrtc QA for codec correctness, the exhaustive simulcast/SVC and RTP metadata combination space, physical device behavior, and desktop portal implementations. Do not require an exhaustive adapter-side codec/profile/layer test matrix or live hardware/display qualification. A smoke test only establishes the exercised adapter path; it does not turn an unimplemented API or a demonstrated failure into a pass. Record fixture-dependent or unexercised adapter behaviors as such, rather than describing them as upstream failures or silently counting them as passed.

## Raw and encoded media

| Contract | Public Rust surface | Evidence and limit |
|---|---|---|
| Caller-fed PCM and decoded sink with format, timing, and bounded loss | `AudioPcmFrame`, `AudioSource::push_frame`, `AudioSink`, `DecodedAudioFrame` | **Partial:** `tests/audio.rs` sends PCM between negotiated peers and checks decoded frames. Other rates/channels and live processing paths are not comprehensively qualified. |
| Owned I420/NV12, rotation, strides, decoded sink | `VideoFrameBuffer`, `VideoFrame`, `VideoSource`, `VideoSink` | **Partial:** `tests/video.rs` covers NV12 conversion, bad planes, retention, and decoded frames; not every format/rotation combination. |
| Built-in codec discovery and caller-supplied encoders/decoders | `VideoEncoderFactoryHandle`, `VideoDecoderFactoryHandle`, `VideoEncoder`, `VideoDecoder`, video capabilities | **Partial:** `tests/video.rs` injects codecs and validates frames. Available VP8/VP9/AV1 depend on the artifact; do not infer unsupported profiles. `AudioEncoderFactory` and `AudioDecoderFactory` currently offer built-in factories only, not caller-defined implementations or support queries. |
| Direct encoded Opus input and output without codec invocation | `EncodedAudioSource`, `OpusInputFrame`, `EncodedAudioSink` | **Partial:** `tests/encoded_audio.rs` exercises direct mono Opus send/receive on two tracks with byte-identical payloads, malformed input, and bounded backpressure. Stereo and a separately instrumented encode/decode-absent proof are not established. |
| Direct encoded video input and output, profile/packetization constraints | `EncodedVideoInput`, `EncodedVideoSource`, `EncodedVideoAccessUnit`, `EncodedVideoMetadata`, `EncodedVideoSink`; legacy `EncodedH264Input` | **Partial:** `tests/video.rs` exercises H.264, VP8, VP9, AV1 and H.265 RTP send/receive without invoking software encoders; separate H.264 streams and teardown are checked. The legacy helper supports constrained-baseline H.264 packetization mode 1; the generic helper accepts negotiated formats but requires matching externally encoded bitstreams and is limited by the built artifact's packetizers. AV1 temporal delimiters and HEVC Annex B start-code widths may be normalized by RTP. No video encoding library is bundled by this adapter. |
| Received Opus RTP level and voice-activity metadata | `EncodedAudioFrame::audio_level_dbov`, `voice_activity`, `sequence_number` | **Partial:** the pinned native incoming `Type()` getter directly projects RFC6464 V when `AudioLevel()` is present. `tests/encoded_audio.rs` checks negotiated true V and absent-extension unknown on real peer links, including ASan. Independent producer level/V overrides and a received false-V fixture remain unqualified. No PCM or decoder speech inference is used. |
| Stream identity, timestamp, frame/layer metadata, bypass and replacement | Encoded video/audio frame types and sender encoding parameters | **Partial:** H.264 stream identity and replacement are tested in `tests/video.rs`; Opus input/output identity is checked on two tracks in `tests/encoded_audio.rs`. Direct single-encoding H.264 L1T3 DD frame IDs, temporal indices, dependencies and native four-target DTIs are checked in `tests/video.rs`, `tests/production_session.rs` and `tests/controlled_media.rs`. Native extension negotiation and five-by-four bitrate guidance are exposed. Received VLA is unavailable through the pinned public native APIs; sender allocation/negotiation is not receipt evidence. Test-only offline native parsing of actual clear sender packets validates full three-rung VLA, RID/SSRC/index association and full packet sizes on ordinary and impaired links; it does not authenticate SRTP or expose received VLA. The probe test requires a matching exported SDK and is explicitly ignored by default. Synthetic opaque 4 KiB VCL tails now qualify exact native fragmentation/reassembly with clear syntax for no-DD and L1T3/DD on ordinary and impaired links; fragmented three-rung sender-only input preserves native full VLA/RID/SSRC and packet-size bounds. This is neither crypto/authentication nor simultaneous three-rung received fidelity. Broader opaque, audio and capture-time qualification remains incomplete. |
| Simulcast/SVC negotiated behavior, per-encoding delivery | RID configuration and sender parameters | **Partial:** `tests/video.rs` validates RID configuration and rejects unsupported encoded layers. Direct H.264 L1T3 temporal delivery is qualified at the exercised production/controlled boundaries. Direct three-rung H.264 sender batching is qualified with native allocated callbacks, distinct outbound RID/SSRC statistics and controlled replay; input admission/budget accounting and ambiguous collapsed/single-encoder fallback rejection are tested. Native three-stream initialization is required. Stock simultaneous reception of all three rungs is not supported, and sender-only answers/statistics are not received-DD/VLA proof. H.264 spatial SVC is outside the agent-ready scope. |
| Keyframe requests and encoder rate/lifecycle | `EncodedVideoSource::take_keyframe_request`, `latest_rate_control`, `take_encoder_error`, `VideoEncoder` callbacks | **Partial:** native Encode-keyed requests, producer-supplied recovery, layered bitrate snapshots, source-keyed rejection and actor readiness are exercised by video/actor/controlled tests. No idle-source keyframe notification is promised. Multi-stream/replacement feedback isolation needs fuller qualification. |
| Echo cancellation, suppression, gain control and encoded bypass semantics | `AudioProcessingConfig`, per-track `AudioProcessingOptions`, `audio_processing_state()` | **Partial:** factory-time software AEC/NS/AGC and track-level automatic/platform/software choices are exposed; headless construction, options, and state have focused tests in `tests/audio_processing.rs`. Live native-device effects and mixed simultaneous-track behavior are untested. Encoded Opus cannot share this adapter's PCM processor and rejects processing options. |

## External-driver and acceptance infrastructure

| Contract | Public Rust surface | Evidence and limit |
|---|---|---|
| Manual clock, cooperative task queues, deadline and seed lease | `ManualClock`, `TaskQueueFactory::cooperative`, `run_ready`, `next_deadline`, `RandomnessLease` | **Partial:** `tests/execution.rs` proves queued work ordering and seed ownership. This does not prove that libwebrtc peer, codec and device work is fully caller-pumped. |
| Controlled packets, delay/reorder/loss/duplicate, multiple endpoints | `ControlledSimulatedNetwork`, `NetworkEndpoint`, `next_packet`, `deliver_copy`, `drop_packet` | **Partial:** `tests/controlled_driver.rs` demonstrates delayed, reordered, duplicated and dropped UDP packets with no autonomous adapter network thread; `tests/network.rs` exercises the preexisting threaded variant. `tests/controlled_driver.rs` resolves configured STUN and TURN hostnames from `add_dns_record` through real peers into outbound UDP and TCP decisions, delivers a TCP connect, observes TURN bytes, and checks a TURN/TLS ClientHello. `tests/controlled_turn_tls.rs` delivers simulated TCP bytes to a real in-memory TLS server with a fixture CA, verifies a decrypted TURN request after certificate validation, then uses a coturn fixture to authenticate and gather a relay candidate under relay-only ICE policy. A second controlled test connects two relay-only peers through coturn over caller-delivered TURN/TLS bytes and delivers data-channel application bytes end to end. The coturn fixture explicitly permits loopback relay peers. Incoming TCP listening and independently validated external TURN interoperability remain unproved. |
| Same-thread virtual-time-only multi-peer trace, pending close | `ControlledPeerDriver`, `ControlledSimulatedNetwork`, cooperative `TaskQueueFactory` | **Partial:** `tests/controlled_driver.rs` exchanges gathered SDP and establishes ICE between two real peers without a wall-clock wait, and checks for new native threads at construction and connection. A repeatable seeded connection-state and delivered-data trace and close with a pending offer are exercised. Without explicit `controlled_media()` admission, peers still reject media. The admitted Opus/VP8 real-decoding path has continuous syscall/lifetime evidence and ordered impaired replay in `tests/controlled_media.rs`. Direct H.264/no-DD and H.264 L1T3/DD encoded-only paths now exercise caller-pumped real transport, loss/delay and logical replay there. Encoded receiver closure is terminal; H.264 decoded sinks reject explicitly. Continuous syscall monitoring spans 17 complete scoped lifecycles, including H.264 and subsequent world reacquisition, with no child/thread creation or physical socket calls inside them. Ordinary and ASan/leak-detection video/actor/controlled regressions pass; this does not admit arbitrary codecs, processing, or physical devices. |
| Real SFU Opus/H.264 interoperability | Downstream higher-level project | **Out of scope:** adapter tests cover the named public APIs and negative configuration paths; integration against a real SFU is not this library's gate. |
| Source, matching artifacts, fresh Rust-only consumer, sanitizer | `just check`, Linux `_export` and `_runtime-test`, `verify-artifact`, ASan native runtime | **Partial:** Linux core/native exports and runtime suites plus the fresh Rust-only core consumer pass for this bridge. Native ASan with leak detection passed for this bridge and controlled-network candidate; core ASan and full simulator/codec coverage are not established. These checks do not qualify physical devices, portal-service outcomes or full controlled-mode coverage. |

Public-only executable examples: [`core_media.rs`](../examples/core_media.rs) stages raw PCM/I420 and optional externally encoded H.264, [`external_driver.rs`](../examples/external_driver.rs) constructs a caller-pumped peer with a cooperative queue and controlled UDP delivery, and [`native_devices.rs`](../examples/native_devices.rs) inspects opt-in devices. The examples are setup demonstrations, not evidence of a full call, all libwebrtc background paths, real SFU or physical device path. The corresponding integration tests live in `tests/audio.rs`, `tests/video.rs`, `tests/execution.rs`, `tests/network.rs`, and `tests/controlled_driver.rs`. No public unsafe CXX handles are needed.
