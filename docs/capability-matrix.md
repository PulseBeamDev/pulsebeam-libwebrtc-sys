# Linux x86_64 capability and evidence matrix

This matrix tracks the approved Linux x86_64 API completeness contract. The public API and evidence links below stand alone. **Pass** means the named test actually exercises the claim with a matching artifact. **Partial** means only the specified subset is exercised. **Gap** means no qualifying API or test exists. Headless tests do not qualify a physical device or all possible libwebrtc background work. Real SFU interoperability belongs to the higher-level project.

## Core ownership, peer, and transport

| Contract | Public Rust surface | Evidence and limit |
|---|---|---|
| Typed ownership, errors, closed resources, release | `PeerConnectionFactory`, `PeerConnection`, `PeerErrorKind`, resource `close` and `Drop` | **Partial:** `tests/peer.rs`, `tests/network.rs`, `tests/video.rs`; native ASan runtime suite passes. Not every provider/codec teardown is independently qualified. |
| Operation identity, cancellation, ordering, bounded events | `OperationId`, `OperationCompletion`, `PeerConnectionEvent`, `try_next_event` | **Partial:** `tests/peer.rs`, `tests/data_channel.rs`. A complete exactly-once proof across all shutdown races is absent. |
| ICE credentials, candidate policy, hostname, IPv4/IPv6, gather-then-SDP | `IceServer`, `IceTransportPolicy`, `PeerConfiguration`, offer/answer and description methods | **Partial:** `tests/peer.rs` proves simulated IPv4/IPv6 STUN; `tests/turn.rs` proves local coturn UDP/TCP/TLS, credential and certificate failure, and interrupt. Real global IPv6 TURN test is ignored by default when the host has no global address. No individual candidate forwarding is needed in these tests. |
| ICE restart, rollback, pending/current descriptions, state/events | `create_ice_restart_offer`, `descriptions`, `set_local_description`, `set_remote_description`, `PeerConnectionEvent` | **Pass for tested paths:** `tests/peer.rs`, `tests/turn.rs`; not a real SFU qualification. |
| Multiple tracks, directions, replace/remove, sender/receiver/MID, encoding updates | `add_audio_transceiver`, `add_video_transceiver_with_rids`, `RtpSender`, `RtpReceiver`, `RtpTransceiver` | **Partial:** `tests/video.rs` tests replacement, stop, RID and transaction validation; concurrent multi-track media renegotiation is not demonstrated. |
| Codec capabilities and unsupported configurations | `video_sender_capabilities`, `video_receiver_capabilities`, codec preference and sender parameters | **Partial:** `tests/video.rs` checks unsupported RID/encoding values and H.264 paths; SVC mode support and negotiated metadata need fuller qualification. |
| Data channels, reliability modes, bytes, readiness, closure | `DataChannelConfiguration`, `DataChannelSendResult`, `DataChannelEvent`, `buffered_amount`, `close` | **Partial:** `tests/data_channel.rs` exercises negotiated/in-band exchange, invalid configurations, and shutdown on two peers; `tests/controlled_driver.rs` delivers text and binary messages in both directions across real controlled peers with virtual-time-only progress. |
| Timestamped linked transport/media/data stats | `request_stats`, `PeerStatsRecord`, `CandidatePairStats`, `TransportStats`, `InboundRtpStats`, `OutboundRtpStats`, `DataChannelStats` | **Partial:** `tests/peer.rs` and `tests/data_channel.rs` check selected relationships and values. Not every metric and unavailable-vs-zero state is fixture-qualified. |

## Raw and encoded media

| Contract | Public Rust surface | Evidence and limit |
|---|---|---|
| Caller-fed PCM and decoded sink with format, timing, and bounded loss | `AudioPcmFrame`, `AudioSource::push_frame`, `AudioSink`, `DecodedAudioFrame` | **Partial:** `tests/audio.rs` sends PCM between negotiated peers and checks decoded frames. Other rates/channels and live processing paths are not comprehensively qualified. |
| Owned I420/NV12, rotation, strides, decoded sink | `VideoFrameBuffer`, `VideoFrame`, `VideoSource`, `VideoSink` | **Partial:** `tests/video.rs` covers NV12 conversion, bad planes, retention, and decoded frames; not every format/rotation combination. |
| Built-in codec discovery and caller-supplied encoders/decoders | `VideoEncoderFactoryHandle`, `VideoDecoderFactoryHandle`, `VideoEncoder`, `VideoDecoder`, video capabilities | **Partial:** `tests/video.rs` injects codecs and validates frames. Available VP8/VP9/AV1 depend on the artifact; do not infer unsupported profiles. `AudioEncoderFactory` and `AudioDecoderFactory` currently offer built-in factories only, not caller-defined implementations or support queries. |
| Direct encoded Opus input and output without codec invocation | `EncodedAudioSink` supports receiving Opus packets | **Gap for input:** `tests/encoded_audio.rs` covers encoded Opus receive without a decoded sink; there is no public direct encoded Opus source. |
| Direct encoded H.264 input and output, profile/packetization constraints | `EncodedH264Input`, `EncodedH264Source`, `EncodedVideoSink`, `H264AccessUnit` | **Partial:** `tests/video.rs` exercises direct send/receive, separate streams, teardown, and unsupported sender layers. A codec-absent profile/packetization and encode/decode-absent proof is missing. No H.264 library is bundled. |
| Stream identity, timestamp, frame/layer metadata, bypass and replacement | Encoded video/audio frame types and sender encoding parameters | **Partial:** H.264 stream identity and replacement are tested in `tests/video.rs`; complete dependency-descriptor, allocation and absolute-capture-time round trips are not demonstrated. Encoded Opus input is unavailable. |
| Simulcast/SVC negotiated behavior, per-encoding delivery | RID configuration and sender parameters | **Partial:** `tests/video.rs` validates RID configuration and rejects unsupported encoded layers. Real negotiated simulcast, SVC modes, and per-encoding delivery are not qualified. |
| Keyframe requests and encoder rate/lifecycle | `EncodedH264Source::take_keyframe_request`, `latest_rate_control`, `VideoEncoder` callbacks | **Partial:** provider callback and request paths exist; keyframe recovery with multiple live streams is unproven. |
| Echo cancellation, suppression, gain control and encoded bypass semantics | No public APM control or availability query | **Gap:** do not claim raw processing control or processing of bypassed encoded media. |

## Native Linux devices (feature `native`)

| Contract | Public Rust surface | Evidence and limit |
|---|---|---|
| Explicit ALSA/PulseAudio ADM opt-in, enumerate/select, start/stop and routing | `PeerConnectionFactoryBuilder::native_audio`, `audio_devices`, `select_audio_device`, `create_microphone_track`, `PeerConnection::set_native_audio_enabled` | **Partial:** `tests/device_smoke.rs` checks construction/failure, enumeration, invalid selection, toggle and close; native ASan suite checks teardown/thread affinity. No actual microphone-to-peer or speaker playout is proven in headless CI. |
| Camera identity, formats, capture, delivery, repeated shutdown | `camera_devices`, `camera_formats`, `open_camera`, `CameraCapture::status`, `stop` | **Partial:** `tests/device_smoke.rs` handles absent devices, invalid ID and optional accessible capture. Delivery and physical device removal cannot be proven on a hardware-free host. |
| X11 screen/window and Wayland portal source selection | `screen_sources`, `window_sources`, `open_screen`, `open_window`, `ScreenCapture::capture_next_frame` | **Partial:** `tests/device_smoke.rs` checks enumeration and invalid IDs. Portal source IDs can be placeholders, not unrestricted windows. No display or portal consent fixture exists in CI. |
| Pending, cancellation, denial, unavailable portal, capture failure, session closure | `ScreenCaptureStatus::{PendingSelection,CancelledOrDenied,Failed,PortalSessionClosed}` | **Partial:** adapter observes session close through upstream PipeWire notifier. Pinned upstream maps portal response 1 to user-cancelled, response 2 and proxy failure to generic error. Denial versus cancellation and missing service versus other errors cannot be reported distinctly through these callbacks. Live portal outcomes are untested. |
| Snapshot refresh, loss, multi-handle cleanup, explicit opt-in | New enumeration calls, capture `status`, `stop`, `Drop`, default headless factory | **Partial:** invalid input, repeat stop and absent-device behavior in `tests/device_smoke.rs`; no live device-loss, overlapping capture or session-close injection. `native` does not itself request consent or open a device. `core` has no device API. |

## External-driver and acceptance infrastructure

| Contract | Public Rust surface | Evidence and limit |
|---|---|---|
| Manual clock, cooperative task queues, deadline and seed lease | `ManualClock`, `TaskQueueFactory::cooperative`, `run_ready`, `next_deadline`, `RandomnessLease` | **Partial:** `tests/execution.rs` proves queued work ordering and seed ownership. This does not prove that libwebrtc peer, codec and device work is fully caller-pumped. |
| Controlled packets, delay/reorder/loss/duplicate, multiple endpoints | `ControlledSimulatedNetwork`, `NetworkEndpoint`, `next_packet`, `deliver_copy`, `drop_packet` | **Partial:** `tests/controlled_driver.rs` demonstrates delayed, reordered, duplicated and dropped UDP packets with no autonomous adapter network thread; `tests/network.rs` exercises the preexisting threaded variant. `tests/controlled_driver.rs` resolves configured STUN and TURN hostnames from `add_dns_record` through real peers into outbound UDP and TCP decisions, delivers a TCP connect, observes TURN bytes and drops them. TCP server response/incoming bytes, TCP listening, TLS, and end-to-end TURN-over-TCP outcomes remain unproved or unsupported. |
| Same-thread virtual-time-only multi-peer trace, pending close | `ControlledPeerDriver`, `ControlledSimulatedNetwork`, cooperative `TaskQueueFactory` | **Partial:** `tests/controlled_driver.rs` exchanges gathered SDP and establishes ICE between two real peers without a wall-clock wait, and checks for new native threads at construction and connection. A repeatable seeded connection-state and delivered-data trace and close with a pending offer are exercised. Controlled peers explicitly reject audio/video transceivers and local/remote media SDP: upstream video receive-stream recreation waits on its decode queue, while audio sender teardown waits on its encoder queue. Neither queue can progress while the caller-pumped thread is blocked. Codec work, packet scheduling around peer media, and proof that no transient native thread runs remain unverified. |
| Real SFU Opus/H.264 interoperability | Downstream higher-level project | **Out of scope:** adapter tests cover the named public APIs and negative configuration paths; integration against a real SFU is not this library's gate. |
| Source, matching artifacts, fresh Rust-only consumer, sanitizer | `just check`, Linux `_export` and `_runtime-test`, `verify-artifact`, ASan native runtime | **Partial:** Linux core/native exports and runtime suites plus the fresh Rust-only core consumer pass for this bridge. Native ASan with leak detection passed for this bridge and controlled-network candidate; core ASan and full simulator/codec coverage are not established. These checks do not qualify physical devices, portal-service outcomes or full controlled-mode coverage. |

Public-only executable examples: [`core_media.rs`](../examples/core_media.rs) stages raw PCM/I420 and optional externally encoded H.264, [`external_driver.rs`](../examples/external_driver.rs) constructs a caller-pumped peer with a cooperative queue and controlled UDP delivery, and [`native_devices.rs`](../examples/native_devices.rs) inspects opt-in devices. The examples are setup demonstrations, not evidence of a full call, all libwebrtc background paths, real SFU or physical device path. The corresponding integration tests live in `tests/audio.rs`, `tests/video.rs`, `tests/execution.rs`, `tests/network.rs`, and `tests/controlled_driver.rs`. No public unsafe CXX handles are needed.
